# 真实 Provider × 浏览器分批测试矩阵

日期：2026-08-29

## 目标与执行原则

本矩阵使用 `tests/real_data/reference_data_manifest.json` 中已校验的九份真实工作簿，验证从浏览器上传、会话绑定、确定性加载、模型路由、工具执行、证据与图表、持久化、刷新恢复到导出的核心用户流程。

每个矩阵场景均是独立、可计数、可停止的真实浏览器套件。场景使用 `M01`～`M06`；同一场景因执行基础设施阻断而重新冻结时，使用独立授权尝试号，例如 `M01-A03`，不得再用 `B01/B02` 同时表示场景和授权序列。

执行原则：

- 每批只执行冻结的浏览器旅程，不追加临时问题或补跑。
- 每批单独冻结 source digest、模型、数据、提示词、oracle、计数启动器、调用上限和唯一报告路径。
- 每批先做零 Provider 自动化与脚本模型浏览器彩排；只有当前批次的精确授权才能启动真实 Provider。
- 同一场景的主请求和辅助请求共用硬计数器；该场景首个 Provider 失败后场景内全局熔断，产品后续逻辑调用只能在本地拒绝，不得再次触达 Provider。新批次须另设整批硬上限，逐场景串行扣账；不得借下一场景重试上一场景的提示词。
- 非阻断 oracle 偏差继续沿同一冻结旅程收集：单序列图、Workbench 标题、根滚动、确认气泡、console 日志、刷新恢复或导出归属失败均记录后继续执行剩余已冻结浏览器步骤，不新增提示词、模型回合或旅程。
- 严重阻断立即终止当前场景的生成：Provider 传输/超时失败、场景调用上限、必须由用户重新选择的非预期确认、文件恢复提问、无法产生后续页面状态的工具/流程错误。已有页面仍可做不增加请求的只读观察；前置状态未产生的检查标记 `blocked`，不能判通过。
- “继续收集”不授权失败重试、补发、模型切换、Provider fallback、额外提示词或补充旅程；浏览器控制连接可在不刷新页面、不重复用户动作的前提下重新绑定同一页面。
- 一个批次内所有已冻结场景各尝试一次，不以前一场景通过为条件。场景异常退出也要在完成隔离和扣账检查后进入下一独立场景，以验证缺陷是场景特有还是跨场景复现；相同错误签名本身不成为跳过其余场景的理由。
- 整批停止仅用于共享安全边界：整批预检/授权/source/data 不匹配、整批调用上限、共享环境或数据归属破坏、前场景进程/在途请求未停止、收据缺失导致实际消费不可确认。局部隔离是否足够不能凭推测；无法证明时标记剩余场景 `not_run` 并说明原因。
- 每场景使用独立进程、workspace、sessions、收据和报告；前场景结束后确认进程退出及真实 calls/blocked_attempts，再把剩余整批预算分配给下一场景。不得清空熔断器、复用旧目录或旧授权。该规则只适用于新冻结批次，不追溯修改 M01-A03。
- 单元/离线、脚本模型浏览器、真实 Provider 浏览器、staging 和 production 是不同证据等级。

## 2026-08-30 增补：异常终止后的覆盖口径

`scripts/acceptance/browser_matrix.py` 提供单次消费的采集控制器：场景级异常只停止该场景后续生成；非阻断 oracle 失败保留后续检查；依赖未满足明确 `blocked`；无法证明进程隔离与消费计数时整批 fail-closed。控制器本身不发送 Provider 请求，也不替代授权启动器。

故障注入回归必须覆盖：六个场景全部在分析阶段异常仍六个都被访问、同一错误跨场景重复、已有状态只读检查继续、缺失依赖受阻、局部熔断后不再发送、收据/隔离失效整批停止、上限中途耗尽、重复执行拒绝。此类回归仅证明控制流，不能记作六场景真实 Provider 或完整浏览器通过。

## 每批共同断言

1. 页面加载的是当前源码带内容哈希的静态资源；浏览器 console error/warning 为 0。
2. 上传票据不泄露服务器路径，文件哈希与冻结数据一致；取消附件会删除未绑定暂存。
3. 文件在首个模型请求前归属当前会话并完成确定性加载；不得依赖共享 inbox。
4. 不出现“文件不存在、重新上传、提供完整路径”类 `ask_user_question`。
5. 所需工具均有成功收据，工具 error event 为 0；证据、图表和导出物必须属于当前会话。
6. `turn_end` 后 Workbench 状态稳定；确认恢复期间 composer 保持禁用；刷新或切换会话后最终回答、证据和产出物可恢复，持久化确认协议不得泄露到用户气泡。
7. Provider 调用只使用冻结模型、温度、超时和 token 阶梯；无重试、无 stream→sync 补发、无模型/Provider fallback。
8. 只写入该批次冻结的隔离 workspace、sessions、计数收据和报告路径；不执行 Git、部署、staging、production 或原会话删除。

## 明确不混入本矩阵的范围

知识/记忆治理、MCP 外部连接、管理后台 CRUD、任务调度、项目绑定和 staging/production 属于不同权限面，应另建 UI/集成矩阵；把它们塞进分析旅程会让失败无法归因，也会扩大授权范围。本矩阵仍保留 Route A 的完整产品面，只把本轮真实 Provider 预算集中在上传与分析核心路径。
