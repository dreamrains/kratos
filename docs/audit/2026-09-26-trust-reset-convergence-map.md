## 关键纠偏：普通路径零 typed 不能诊断 opt-in 生产者

`AgentLoop(typed_trial=False)` 是正式默认；`_maybe_inject_typed_trial` 在此模式直接返回，已有宿主候选不会进入最终化轮。普通发布提示仍允许模型自行提出 binding，R4 M02/M04 也确曾尝试，但均未形成有效原位 claim。自然 M03-P/N 在显式 opt-in 下各产生六个有效原位 claim，而完整 R4 使用普通路径，六例均为零。因此 R4 的零不能单独判定 opt-in 生产者失效，也不能作为再叠一个生产者的理由。它证明的是：**正式默认尚未采用已开发的局部能力，也不能稳定依靠模型自行写对 binding**；即使 opt-in 已成功，自由散文的正确解释和无据句仍并存。Phase 6/D 的默认处置是明确的产品取舍门，不应通过反复普通路径 E4 伪装成修 bug 来跨过。

## 一条收敛路径，而非无限切片

1. **先消除验收伪障碍和确定性状态错误。** R4 M06 `resolution_params.confirmation_type=metric_definition` 的审计误报用同一持久记录只读复核；R4 原判定文件不改。M02/M04 仅在独立于措辞的任务/关系身份问题有 RED 时修状态机，不因自然句式失败添加词表。
2. **在现有 opt-in 路径做一次正反价值闭环。** 复用唯一 `answer_bindings.v1`、当前 packet/回执/原位 trace。对 R11 原始尺度、R16 方法/分母、M03 六源表+图、M04 当前关系分别记录 `核验事实 / 待核解释 / 具体缺口 / 产物`。若正确解释与无据强断言不能在原位或明确待核区域内区分，停止默认切换；不得把全部自由散文直接删除或交给关键词门冒充证明。
3. **只在有自然有效分母时接真实 Shadow。** 5.3 的调度、预算和故障路径应复用现有 `run_shadow_audit_once` 与账本；5.4 在自然正反 claim 上量化误删、漏检、不可评估与成本。Shadow finding 不增事实、不覆盖确定性失败，最多一次定向修订。
4. **按家族删旧门并同步删镜像测试。** 先列旧门、正误历史、结构所有者、局部处置和代码删减。没有双向证据的族明确保留为 open；不把“Phase 7 实现准备”写作退出，也不为了减少行数去掉唯一安全边界。
5. **集中验收后裁决正式默认。** 完整离线、Provider-disabled E3、冻结授权的自然正反和 M01—M06 E4 分开记账；HTTP 批不包含浏览器点击/视觉。仅当阶段表各项有正反收据后，提交正式默认与回退方案供用户裁决。若现有结构仍无法同时保住解释和限制无据句，应明确提出修改产品策略/计划退出条件，而不是再开启一个补丁循环。

### 已实施的受控边界与下一检查

用户在本基线选择默认关闭的“已核验事实 / 待核验解释”分区。现有 opt-in 最终化轮现在把同版本 binding 的唯一可渲染副本放在已核验区，模型其余原文保留于待核区；无 binding 则没有已核验区，伪造引用仍被原校验拒发。普通默认不变。六来源正例、无绑定、外来事实负例和 trace 校验已有 E2 定向测试。该分区只使不确定性可见，**不证明待核文本正确**；不能据此退役旧散文门或通过 Phase 6/7。下一次验收需要把 R11/R16/M03/M04 的自然正反内容、图表与导出同版本地分层对照；若错误建议虽有标记仍对用户构成不可接受的发布风险，停止正式切换并重新裁决局部隐藏/修订策略，不继续堆词面门。

**Phase 5/C 依赖仍是实质性阻断**：现有 `build_shadow_audit_request` 只接收有宿主原位 trace 的 claim 和其同一行有限邻接文本，`run_shadow_audit_once` 还要求存在 `same_line_untrusted` 才会调度。分区后的独立待核区不会进入该审计输入；不能把“待核”标签当作已经过 Shadow 质量校准，也不能为凑分母偷偷把整段散文关联到一个 claim。若后续要对待核区逐句处置，需要另行设计可定位的解释身份与安全动作，并先证明 R11/R16/M03/M04 的正反价值，属于 Phase 5/6 的明确架构取舍。

### 待裁决的最小契约变更（不预实施）

总计划 §5.1—5.4 的候选答案语义审计与当前“仅 claim 同行邻接”的实现范围不等价。若仍按原完成定义推进，建议只扩展**现有** `publication_audit` 和最终答案 trace：宿主为待核区记录受最终答案 SHA 约束的文本范围与片段 SHA，Shadow 在显式受控入口读取这些范围、用户原问题、现有 packet/回执摘要及已核验 claim；模型 finding 只能定位范围并给出 advisory/一次定向修订建议，不能自建事实或替代确定性失败。按 R11/R16/M03/M04、R7—R21 的正确解释与无据结论校准动作后，才考虑局部降级；届时删除旧的 `same_line_untrusted` 专用路径，避免第二套长期并行的审计目标。`answer_bindings.v1`、planner、账本、浏览器框架和正式默认均不变。此举会改变审计输入/输出契约，须先获用户明确裁决。

另一条路径是保持现有 Shadow 只审 typed 同行文本，待核解释明确永久 `unassessed`，并修改总计划对 Phase 5/C 与 Phase 7 的退出条件；这会保留更多旧散文门或接受更多未局部审核的可见内容，属于目标变更，不能通过把本地回归写绿来暗改。两条路径都不能把已执行 R4、当前 E2 或自然 M03 归档倒填为正式验收。
