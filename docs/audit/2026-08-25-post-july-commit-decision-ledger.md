## 1. 目的与裁决规则

本台账回答四个问题：

1. 7 月以来到底做过什么；
2. 哪些问题值得继续解决；
3. 哪些实现可以作为供体，但不能整包迁移；
4. 哪些路线已经被事实证明会造成能力丢失、错误完成或质量倒退，必须停止使用。

裁决标记：

- **A — 选择性移植**：可以把小而独立、契约清楚的算法、schema、工具或测试移植到 7 月 13 日底座；仍需重新接入主 AgentLoop，并通过能力保全和真实数据门禁。
- **B — 吸收原则/测试**：问题判断正确，原实现耦合过深、层次过多或引入副作用；只复用失败样例、契约、断言和设计原则，不搬运整套实现。
- **C — 仅作历史证据**：保留文档、测试收据或复盘价值，不将实现作为当前方案来源。
- **D — 明确弃用**：路线与项目目标冲突，或已造成严重回归；不得以改名、兼容层或旁路服务的方式复活。

共同约束：

- 任何 A 类提交都不是“直接 cherry-pick 清单”；先提取最小责任，再在现有入口中实现。
- 不建立 `/v2`、第二套 planner、第二个会话真相源或新的平行发布链。
- 不因旧测试通过就宣称可发布；所有证据必须绑定当前 source digest、数据指纹、提示词、模型和浏览器过程。
- 不用兼容层掩盖新旧结构冲突；迁移需一次性、可验证、无损。
- 未经用户单独授权，不调用真实 Provider，不提交、合并、推送、部署、切根或删除历史实现。

| 非破坏性产出写入 | `ed85879` | 同秒覆盖、manifest 与详情不一致 | 原子写入、唯一 ID、manifest 校验 |
| copy-on-write 数据转换 | `2bdb114` | 类型修复污染原始数据 | 原文件只读；派生版本显式绑定与可回溯 |
| 数据驱动停止条件 | `2b38763`、`5ae18cc` | 固定轮次导致分析过浅或无效调用 | 以问题覆盖、风险、不确定性和预算共同停止 |
| 建议作用域 | `7b074df` | 建议超出证据、被全局压制 | 区分数据事实、推断、建议及适用范围 |
| 确定性分组/时间/因子/预测算法 | V01、V08 的 A 类提交 | 旧方法覆盖不足、重复造轮子 | 作为现有工具供体，逐项对照能力台账 |
| Provider 预检与零重试 | V05 | 未授权额外调用、opaque failure | 每个 journey 冻结精确调用次数；失败即停 |
| 语义稳定性分类 | V05/V06 | 把措辞差异误判为质量倒退 | 只对安全、方法、范围、路由和结果漂移 fail closed |

## 6. 明确放弃与删除的路线

| 路线 | 结论 | 理由 |
|---|---|---|
| V2 作为独立产品/运行时 | 删除，不兼容 | 未继承 7 月 13 日能力，真实数据大范围退步 |
| 根路由切换到 V2 | 禁止 | 把有限自测通过误当产品等价 |
| 双 planner、双会话真相源、双发布链 | 禁止 | 造成 stale binding、状态冲突与技术债 |
| 硬发布门统一清空答案 | 删除 | 使可验证的降级结论也无法交付 |
| 阶段完成推导任务完成 | 删除 | 造成假完成与工具结果未回收 |
| 所有分析强制通用图表 | 删除 | 产生无意义或未执行图表 |
| 只删 Workbench 前端 | 删除这种做法 | 留下后端、API、prompt 和数据结构债务 |
| 完全计划文本一致性 | 删除 | Provider 的合理措辞差异不等于语义漂移 |
| 自定义 harness 自证 readiness | 删除 | 无法证明旧功能、真实数据和 Web 体验完整 |
| 固定工具数/固定轮次阀门 | 删除 | 造成浅分析或无效调用；应改为证据驱动停止 |
| token overlap 充当核心假设质量 | 不采用 | 文本重叠不能代表业务假设、方法或证据质量 |

## 7. Gate A 审阅问题

开始业务代码修改前，需要用户确认：

1. 是否接受“V2 整体弃用、局部算法与测试作为供体”的边界；
2. 是否接受 A 类也不直接 cherry-pick，而是在现有主链逐项重写/移植；
3. 是否接受删除硬发布门、假完成推断、通用图表和 UI-only 删除路线；
4. 是否同意把 source-bound、真实进程浏览器、Provider 零重试和语义稳定性分类提升为发布门禁；
5. 是否有某个提交或功能必须保留，但本台账误判为 B/C/D。

未确认前，本台账只形成实施边界，不授权修改业务代码。
