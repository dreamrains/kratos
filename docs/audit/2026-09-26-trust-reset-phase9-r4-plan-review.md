## 4. 收敛顺序与修复准入

1. **先评估自然答案，而非先放松 parser。** 以 R11 正确 D7 边界、R16 M05 已通过方法价值、R4 旧 M03/M04、R7—R21 的误拒/误放和本批六例组成正反矩阵；分别标明可复算事实、正确解释、无据强断言、产物、用户子问题、假设关系。旧文本不倒填为新绑定。
2. **优先修正 Phase 8 的证据分类假阴性。** M06 的确认记录已有结构化 `metric_definition`、已解决状态与选项 B；审计器应读取现有结构并仍拒绝方法审批/无关数据性质提问。此修正仅改变测试判定，不提升产品阶段身份。
3. **再选 Phase 6 的最小产品切口。** M02/M04 的自然绑定尝试须用当前 packet、回执、真实 ID 和单位边界逐块复核；若语法归一化也会把无据句/关系放过，就不接入正式 parser。正确解释的保留、独立无据句的局部处置和宿主可证实缺口必须并列验收。没有同版本权威材料时保持 `unassessed`，不新增词表或 claim 家族。
4. **Phase 5/C 和 Phase 7 服从上述分母与替代证据。** 自然可行动 claim 为 0 时，不启动“误删率通过”宣称；旧门只按具体家族退役，不靠删代码行数、附录或模型总评过关。Phase 6/D 默认发布仍需用户就完整正反证据另作目标裁决。
5. **停止条件。** 若下一改动只是接受更多 fence/字段别名、增加关键词、软化回执/版本/单位、模型自报 `answered`、借尾注遮盖正文、重复 planner/账本/浏览器框架，或仅用新 E4 发现可离线复现问题，停止实现并回到这张矩阵。下一真实批次必须在修复收敛、本地完整验证和新冻结/授权之后；本批不局部重跑。
