# 架构修复实施记录

本记录对应离线实施，不能视为真实 Provider、staging 或 production 验收。

## 已实施的边界调整

- `LLMClient` 的同步、流式、单次及辅助客户端共享可注入 transport。SDK 内重试关闭；产品显式网络重试和显式输出额度策略共用物理尝试上限。默认不再把输出额度乘四，也不在流失败后另发同步请求。取消信号传到已打开的流和重试等待。
- 外部验收 guard 收据升级到 v3；每次发起永久占位，明确 completed/failed/cancelled/unknown、本地停止证明和远端计费未知。close-before-next、提前退出和并发关闭均有回归；无法证明停止继续阻断整批。旧收据不迁移。批次增加已观察发起数，旧 `real_calls` 字段明确只汇总闭合场景。
- 正常和确认恢复共用流式分析循环。回合安全上限只报告未完成；轮数不再强制移除全部工具；单次工具成功不再自动完成整个任务。纠正参数与重复同一错误分开处理，失败的证据写入不能解除 Python 结果待归档状态。
- Web 增加当前会话运行状态的持久化快照和并发执行门禁。页面仅在终态或运行状态快照确认结束后解锁；断流不等于成功，中断请求先进入 cancelling。SSE 读完后再请求 Workbench 投影，保留会话和请求代次防护。
- 嵌套证据输入先校验类型/枚举，错误具体到字段；继续校验本轮收据和数据版本。当前会话工具产物引用使用统一安全解析，跨会话和穿越仍拒绝；长摘要不再覆盖结构化结果。
- 曲线计算直接提供实际/拟合序列；图表可引用当前会话结果文件，并验证成功收据哈希及数据版本。图表、证据记录携带结果归属，导出沿用持久化产物。
- 沙盒 Python 使用可终止子进程；仅传递当前任务允许的数据快照。超时后确认子进程退出，错误不能被登记为成功证据。保留 pd/np/get_dataset 接口，明确 import 的替代方法。
- cohort 工具区分未到观察期的 null 与观测零值，披露首次观测口径和末月不完整。宽转长保留现有 pivot 能力，schema/错误信息明确其参数，不增加虚构的 melt operation。

## 对预算、计数器和测试缺口的架构说明

产品里的输出长度、上下文占用和安全执行上限，与验收脚本的真实请求消费账本，是不同的概念。保留有限的资源保护与可审计请求记录有必要；原实现的问题是自动倍增输出额度、隐藏重试路径、把上下文估算当累计消费、以及把耗尽/任务完成/证据有效混在一起。修复目标是拆开这些职责，而不是把模型循环改成无限执行，也不是让用户反复“升级预算”。外部验收账本仅用于受授权的付费测试，不能控制产品的分析有效性。

此前大量离线通过没有证明这些边界可靠：使用合成成功响应跳过了模型实际嵌套参数错误；检查产物存在不等于模型按返回引用能读到；SSE 消息到达不等于持久化完成；单场景或静态断言不覆盖确认恢复、切换及刷新。M02–M06 更未完成真实全旅程。B01 又暴露预演脚本未先走完整序列的测试基础设施缺口。本轮把这些失败写入实际上下游集成回归，同时仍要求当前源码浏览器证据，不能用测试数量替代覆盖说明。

旧 MATRIX-A01 账本保持不变：22 次发起、最后一条仍为 started。新的本地取消语义不能追溯证明旧请求的 Provider 终态或计费。当前工作不新增真实 Provider 或 Git 写操作授权。

## B05 计数持久化失败与 Windows 原子替换

B05 源码 `228481337f03fece8815929a7e4601108b4a836b17e6b749343a4be0cf1dca20`，只启动 M01，一个提示词和一次确认恢复。共 3 次脚本请求，正式收据为 2 completed + 1 started；真实 Provider 为零。第 3 条流结束时发生本地 PermissionError，临时收据含 completed，但正式收据没有闭合。按共享计数规则停止整批，M02–M06 及故障旅程 blocked_not_started；没有刷新或导出。服务强制退出、主控制页关闭、视口恢复。旧收据和临时文件都保留，未将临时内容冒充正式终态。
