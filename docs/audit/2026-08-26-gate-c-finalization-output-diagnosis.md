## 根因

仅以 `tools=None` 关闭 schema 不足：两个模型响应都把后续工具调用编码为正文中的 DSML/tool-call 标记。LiteLLM 响应中没有结构化 `tool_calls`，原 loop 将其当成最终文本并发布；由此既没有执行工具，也没有形成可发布的数值结论。

本诊断只记录形态和结论，不在收据中复制 Provider 正文或推理内容。

## 修复

当前受控源码摘要：`sha256:f7ec450a1c09ca5cc58a97f0418d3ab434ac102901dc2f85dad512b150f70c1b`。

1. 最终化提示明确禁止 tool tags、`tool_calls` 和索取更多工具。
2. 若最终化轮仍输出 DSML/OpenAI 风格的伪工具标记，loop 丢弃该正文、不向用户发布、不执行其中内容。
3. loop 至多追加一次仍为 `tools=None` 的最终化纠正轮；该轮要求直接依据已有已验证结果回答。
4. 第二次伪工具标记终止为明确的、可见的最终化失败，不形成无界循环或隐式重试。

这保留模型推理；不设置 `reasoning_effort`，不切换模型，不改变数据或计算结果。
