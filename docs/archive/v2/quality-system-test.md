## 二、总体判断

**v2 在"统计严谨性、诚实性、确定性、可复现性"上显著优于旧系统；但在"能力覆盖面、答案信息量、可操作性"上出现结构性收缩。**
6 个真数据场景中 4 个以拒绝/零结果/静默收窄告终；用户明确索要运营建议时得到零建议。
根本原因不是 bug，而是架构选择：**LLM 仅做一次路由，分析由 8 种确定性引擎执行，答案为模板拼接**。
旧系统"LLM+工具自由分析"的广度被换成了严谨与可控；直连 LLM 基线则证明纯 LLM 会编造统计量——两个极端都不对。

## 三、五个关注点逐项结论

### 1. 是否过分保守 → 是，且形态特殊
- 保守不体现为"删结论"，而体现为**方法目录过窄导致的诚实拒绝**：S1（曲线拟合不在目录）、S2b（>2 组）、S4（配对设计）、S5（脏列+组合单位）。
- S4 用户明确写"请给出运营建议"，答案零建议、零跟进群体、零下一步（recommendation 未触发）。
- S2 零结果：13 个候选因素中 10 个被 VIF 剔除后模型无显著项 → 用户得到的信息量为零，无双变量关联排序等降级路径。
- 正面：拒绝本身统计上大多正确（S4 配对设计识别、S5 脏列不可绑定、S1 无拟合能力如实说明）。

### 2. 对比大模型输出是否过分裁剪 → "裁剪"不适用，但存在两种同构损失
- v2 中 LLM 从不产出结论文本，**不存在对 LLM 文本的删改**（架构上不可能）。
- 同构损失 A（S3 静默收窄）：planner rationale 明确知道"banner/激励视频未提供、占比与关联无法分析"，但答案不披露，三部分问题只答了一部分且不告知。
- 同构损失 B（表达层模板化）：直答 ~100 字符级、无业务翻译、无 So-What；B 基线同题输出 3200-3600 字符含方法表、业务解读、优先级建议。

### 3. 错误与异常处理 → 基本健康，三处问题
- 健康：无 console 错误；无数据时客户端拦截（S6）；needs_input 机制工作良好且问题质量高（S5 第一次澄清切中"分析单元"要害）；授权门不阻碍正常用户；工件落盘完整。
- 问题 a：拒绝文案是 planner 英文 rationale 直出（S1/S5），中文产品体验割裂。
- 问题 b：method/limitation 模板与事实不一致——S2b/S4 未运行分析却输出"主估计使用 Welch…Mann–Whitney 诊断"模板文本，有误导性。
- 问题 c：死路无出路——所有拒绝均不提供替代问法/最近似能力/旧版引导；且拒绝已消耗模型调用配额（S5 澄清后仍 unsupported，共耗 2 次）。

### 4. 广度/深度不足 → 显著不足（本次最严重发现）
- 广度：单会话单数据集（第二次上传直接替换）；多文件综合、占比、跨源关联均不可表达；>2 组分组对比不可表达；组合型分析单位不可绑定。
- 深度：无曲线拟合/参数估计类；无双变量关联排序；无配对检验；无分位数/分布对比；无漏斗/路径；预测仅 naive/drift/seasonal_naive 三候选。
- 答案形态：2-3 个块、数百字；对照 7/11 会话同题数千字+9 图；旧会话的"业务翻译、替代解释排除、优先级行动建议、量化预期效果"全部缺失。

### 5. 严谨性/专业性是否降低 → 未降低，反而提升
- factor：标准化多元 OLS+HC3/聚类稳健 SE+VIF+Holm（7/11 只有相关+GBM，无推断）。
- time_trend：HAC+季节哑变量+Kendall tau（canary 数值与真数据一致）。
- group：Welch+Hedges g+Mann-Whitney 佐证，且识别出配对设计拒绝错误推断（S4）——比"把行当独立样本"的常见错误更专业。
- 但严谨的零结果/拒绝若无降级路径，等于把专业变成了不可用。

## 五、大模型基线对比（B1-B3，同数据同提示词）

- B1（留存拟合）：结构完整（方法/参数表/R²/分期稳健性/行业基准/短中长期建议），但**全部统计量系编造**——"误差为 0.0000"的拟合表在真实 OLS 中不可能；参数（a=0.1683, b=0.612）与真值（0.1879, 0.7164）不符；分期参数、残差检验均为虚构。
- B2（因素分析）：给出回归表、相关验证、恒等链洞察（确认=曝光×点击率×确认率）、策略分组、引用备注列的具体运营事件——**覆盖面最接近 7/11 会话**，但系数/p 值/F 值全部不可信。
- B3（省钱卡）：基于提供的聚合值做了有洞察的解读（结构性变化、折扣侵蚀、分层建议），但虚构了 Mann-Whitney 结论，且关键判断错误（称"前后用户非同一批"——实测 61/62 配对；称"频次上升"——实测订单数下降 29.3%）。
- **Ground truth（实测）**：61 用户配对，下单金额 3980→2837（-28.7%，Wilcoxon p=0.078），实收 3980→2759（-30.7%，p=0.028）——"购卡提升消费"不成立，实收显著下降。
- 结论：**三个形态各有缺失**——v2 严谨但拒绝；纯 LLM 丰富但编造；旧系统（LLM+真实工具）是唯一同时做到"真计算+丰富表达"的形态。

## 六、附：环境发现

- deepseek-v4-flash 思考模式在自由分析任务上会耗尽全部输出预算（实测 76671 字符思考、0 正文）；v2 planner 因仅输出 tool call 而免疫；**legacy 入口的自由分析路径无 thinking 开关，当前模型下存在长任务空输出风险**（LLMClient 未暴露 extra_body/thinking 控制）。

## 七、优化改进清单（按优先级）

### P0 恢复"能算"的覆盖面（决定 v2 可用性上限）
1. **配对前后比较**（Wilcoxon 符号秩/配对 t）：检测到同一分析单位跨两组时自动切换配对路径，而非拒绝（S4 死路；省钱卡场景是该业务的核心问题形态）。
2. **曲线拟合/参数回归** kind（幂律/指数/对数线性化最小二乘+模型对比+拟合表）（S1 死路；留存拟合是游戏数据标配需求）。
3. **多组聚合排序**（>2 组时输出分组聚合+排序+置信标注+图，而非拒绝）（S2b/S5 死路）。
4. **多数据集支持**（同会话多文件、按时间对齐的趋势并列/关联；UI 多文件上传）（S3）。
5. **脏数据自愈**：object→numeric 安全转换尝试（转换成功率/损失行数披露），失败才拒绝（S5 卖量收入）。

### P1 表达层与答案质量（决定"严谨"能否转化为"有用"）
6. **范围披露块**：把 planner rationale 中的范围收窄（未回答的部分及原因）渲染进最终答案（S3 静默收窄是当前最典型的"不合理删改"同构问题）。
7. **拒绝时模板一致性**：未运行分析时不得输出 Welch 等方法模板（S2b/S4 误导性文本）；拒绝文案中文化+提供替代问法/最近似能力/旧版入口引导。
8. **建议引擎触发条件放宽**：用户显式索要建议时，即使只有描述性发现也应输出（标注为提示性、非数据支持）；理想形态=确定性发现+LLM 受约束生成的业务解读。
9. **零结果降级路径**：因素分析无显著项时自动补充双变量关联排序（描述性、明确标注"未经多变量调整"）（S2）。
10. **答案正文自含口径**：指标名、聚合口径、数据范围写进直答正文，不依赖图表（S3 "0.402/天"未指名是内购收入）。

### P2 细节与健壮性
11. 恒等式/同源指标排除复核：确认率（与人均确认共享分子语义）未被视为恒等特征（S2 疑点，需查 factor.py 排除逻辑）。
12. 无数据时的状态文案：误显示"上传失败"（实为"未上传"）。
13. LLMClient 暴露 thinking/extra_body 控制，legacy 长分析任务防思考失控。
14. needs_input 的单位下拉无法表达"组合列"单位（S5）；可考虑支持多选或组合列派生。

### 战略层（需用户决策）
v2 当前是"确定性引擎+窄目录"。三条路线：a) 持续扩目录（P0 路线，工程量大但保持可控）；b) 目录外需求 fallback 到 legacy AgentLoop（LLM+工具）并明确标注证据等级；c) 混合架构——把确定性引擎作为工具暴露给 LLM 分析循环（保留计算的确定性，恢复表达的丰富度）。B 基线证明不能回到纯 LLM；旧系统证明 LLM+真工具可行。建议以 c) 为中长期方向、b) 为短期止血、a) 中优先做 1-3。
