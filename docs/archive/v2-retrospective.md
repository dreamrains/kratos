## 它证明了什么（资产）

1. **严谨性可以工程化**：HAC/Welch+Hedges g/配对识别/Holm/VIF/多族拟合对比/claim 分级——确定性引擎输出的统计从未出错，同数据同数值可复现
2. **校验合同可行**：compile_answer 的数值一致性/引用实存/等级上限三重校验是有效的信任边界（新线以标注式改造回收）
3. **发布流程纪律**：成组 provider 授权、source digest 冻结、证据链工具化——新线测试流程直接继承
4. B1 批次（配对/多组/拟合/自愈/降级五件）在归档前完成，成为新线 R2 的直接弹药

## 病理（为什么成了删减版）

四个环节，全部有据：
1. **场景驱动目录**：8 个方法族来自代表性场景，从未对 v1 能力面（40+ 工具/13 剧本/意图体系/知识系统/web 十类）做对齐盘点——目录外的能力无声消失
2. **"保留成熟工具"承诺走样**：ResultContract 要求结构化输出，40 个 v1 工具都不满足；walking-skeleton 节奏下"重写 8 个"快于"改造 40 个"——每个局部理性，总和背离总纲
3. **自指性验收**：release matrix 18 项全部验证"已支持路径的正确性"，矩阵覆盖面=v2 自己声明的范围——18/18 全绿与 4/6 死路同时为真
4. **优先级压力**：'尽快替换发布'目标下，带回滚的切换被当作终点线；能力债因无任何 artifact 列出而不可见

**一句话病理**：能力对齐从未成为切换的前置条件——设计没定义、matrix 没测量、流程没拦截。（另一面的公道话：对 run_python 自由执行/破坏式发布的排除是有意且正确的。）

## 教训（给未来的自己）

1. 替换型重构必须先产出"被替换方能力面清单"，且作为切换验收的一部分
2. "保留 XX"的承诺要清单化验收，否则会在局部理性中蒸发
3. 验收矩阵不能自指——必须有"对外部基准（前版本/真实需求）的覆盖"层
4. 当"重写比改造快"的诱惑出现时，检查是否正在背离总纲
5. 第二系统效应是真实的：v2 的 spec §23.1 自己警告过，然后精确地踩了进去
