# 可信回答与发布产品需求

版本：2.0；更新：2026-10-10。与[产品PRD](data-agent-product-requirements.md)、[现行设计](../superpowers/specs/2026-09-30-trusted-answer-pipeline-redesign.md)共同定义当前合同；实施状态只见[唯一总计划](../superpowers/plans/2026-09-22-analysis-agent-trust-reset-plan.md)。本合同是目标，不是当前实现通过声明。

## 1. 成功定义与需求

一次回答对有效原需求提供正确、可见、有用且可追溯的交付，精确说明真正未完成部分。知识咨询无需数据回执；数据事实必须有结构证据。拒绝错误和完成合法任务必须同时成立。

| ID | 必须行为 | 禁止替代 |
| --- | --- | --- |
| PUB-01 | 同步、流式、确认恢复调用一个发布服务 | 多个终局builder、旧自由正文fallback |
| PUB-02 | 结构化claim唯一承载数据事实；宿主核验和原位渲染 | 从散文猜值/单位/来源；模型自报verified |
| PUB-03 | 原需求生命周期、原文来源、交付和逐项结果完整 | 相关文字/内部ID存在就算完整；模型自选分母 |
| PUB-04 | 完整事实组与可恢复详情 | 只挑最近/最大值，拆散对象/指标/单位/窗口 |
| PUB-05 | 可定位错误局部拒绝，独立正确内容保留 | 一个坏片段/审核超时清空整答 |
| PUB-06 | 有用解释、竞争假设、条件行动与一次有界审核 | 全部withheld或追加散文词表/第二审核 |
| PUB-07 | 风格真实变化，必要事实和边界保持 | 所有受众同一摘要；靠长文虚构丰富内容 |
| PUB-08 | 宿主核验封闭算术/单位/日期/来源/确认 | LLM审核批准确定性错误 |
| PUB-09 | 当前原测量核验假设关系，公开状态和依据 | 文本相似当支持，描述方向当因果 |
| PUB-10 | SSE/保存/工作台/图/刷新/导出同一接受身份 | 导出latest猜测，前端再裁决事实 |
| PUB-11 | 无文件咨询、绑定既有结果的续问均可用 | 所有无回执回答失败；knowledge标签绕过事实权威 |
| PUB-12 | 默认正常路径先跨接口本地验证，再精确冻结真实调用 | 试验开关或手工状态通过代替默认链 |

## 2. 权威划分

| 所有者 | 能证明 | 不能证明 |
| --- | --- | --- |
| 原请求与有效业务确认 | 目标、口径、范围、偏好及授权 | 数据存在、统计显著、因果/预测有效 |
| 工具/宿主原回执 | 实际执行、参数、读取、来源版本、原结果摘要 | 模型正确理解了完整业务任务 |
| 生产者业务合同与事实校验 | 具体测量/产物语义和可核方法信息；值/来源/范围匹配 | 未核方法前提或任意Python业务正确性 |
| 模型结构草案 | 组织、解释、假设候选、条件建议和引用提议 | 新事实值、擅改目标、授予checked |
| 既有一次局部审核 | 指出开放片段中的无据断言、条件遗漏、误导或价值损失 | 改事实/范围，推翻宿主拒绝，保证所有语义正确 |
| 渲染/提交/公开历史 | 接受对象的原位显示、同一身份保存和恢复 | 再次分析、重判事实或补模型没有交付的解释 |
| 检索、记忆、EvidenceRecord | 研究注解、查找和咨询背景 | 当前计算事实权威 |

来源字节正确、工具执行成功、算法实现正确、方法适用、业务解释成立是不同证明层次。不能用一个confidence/verified标签跨层授信。

## 3. 需求—执行—事实—回答合同

1. 原需求来自真实消息及其有效历史，保存业务目标/约束与revision；模型拆分提议不自动证明完整。多目标独立，等价reuse显式，replace/withdraw原子。非法范围不静默删除，记录未决原因。
2. 有限探索可了解当前授权数据；正式计算派发前声明交付、原目标、步骤、全部来源/版本及业务参数。探索回执不能事后改成正式完成。
3. 同业务范围可有记录地追加交付，原义务/ID/证据保留；变更目标、来源、窗口/口径须显式变更。既有32/64/12/16边界不因裁剪而“通过”。
4. 生产者或封闭适配合同明确原测量、业务类型、粒度、单位、窗口、分母、方法/验证信息和产物。宿主重建目录，模型只引用ID；不能从JSON形状、标量键或散文猜业务量，未知参数不能过滤后假装匹配。
5. 计算依赖消费已核事实/产物/关系；最终覆盖另核解释、限制、行动义务。共用事实投影，不新增完成账本。工具成功不自动表示业务目标/最终答案完成。
6. 完成目标的事实与同范围解释可用证据分开授权。解释可用当前观察说明缺口，但不能因此把未算预测/另一目标标成完成。synthesis不读原表；宿主只读身份验证不得被误报数据不存在。
7. independent显式多输入，实际读取及派生父源逐项核验；模型生成文件不能凭名称/内容相同冒充上传源。Python执行前参数和回放保留，仍为探索性计算。
8. 全部注册工具保留；非事实效果按其合同证明。不得要求文件操作/知识/任务工具伪造数值claim来“适配”发布。

操作效果合同（2026-10-10用户确认）：沿用原需求、AnalysisPlan、真实ToolResult/回执、宿主目录和同一AcceptedAnswer；新增operation交付及effect引用，核对执行前原目标/参数/权限、实际新对象与父版本或文件字节/扩展状态。纯文件/扩展操作可无dataset_inputs，不制造虚假分析来源；数据操作仍绑定精确来源。操作效果不进入数据事实claim、不新增账本，保存前再次核实际对象，失败/变更/越域不能显示完成。已有交付ID可在同目标同范围重用。

清洗/转换边界（2026-10-10用户确认）：清洗逐列记录实际填补数、策略后与最终缺失及原因；删除记录不计作填补，mean/median仅数值且无法求值不换策略。所选范围未解决缺失标部分完成，明确keep按选择保留缺失。类型转换保留原坏值处理并补齐category，分别记录原缺失、成功/失败转换及新增缺失；不能转换的保留真实新表与部分完成。自动转换继续原建议筛选，公开跳过列，不增加强制转换。沿原effect目录、requirement gap及AcceptedAnswer交付；宿主核实际对象、父源和计数，旧答案复用不得消除缺口。

变换合同：结构化参数按公开优先级覆盖旧params JSON，两种输入由同一函数解析；显式默认值也必须生效。filter/select/rename/sort/group_aggregate/resample/pivot/merge保留，pivot继续含宽转长和长转宽。派发前绑定全部实际来源，merge复用多父派生并保留双方版本；同一回执可交付所需操作效果和原聚合事实，各按原目标声明覆盖，不增完成账本。变换作为写能力串行派发，事实与效果共用参数/全部来源验证。
聚合/重采样裁决：count统计指定列非缺失数，size统计行数；旧count没有目标列必须要求选择列或使用size。重采样沿原日期解析与频率算法，空桶/全缺失sum为未知，真实观测零为零；公开有效/排除记录和缺失/坏日期数。原范围存在日期排除时，实际新表与已知结果保留，事实交付和操作效果均携带同一范围缺口，不签全部完成。预算去重只读源/计划身份，派发前再绑定操作对象；无正式计划应返回原formal_plan_required。
分布合同：保留原均值、ddof=0总体标准差和偏置矩偏度/峰度；补齐同一有限范围的min/25%/50%/75%/max，pandas线性插值，无观测为null，沿原回执持久化与交付。所有选中数值列保留；没有有限观测或退化的统计量为null。Shapiro仅3≤n<5000且非退化时计算，结论为rejected/not_rejected/unknown，未拒绝不证明正态。显式缺列/重复/非数值选择整体拒绝；逐列公开原行数、缺失、非有限排除与有效数，非有限排除沿同一交付缺口保留已计算量和原范围部分完成。宿主核对实际来源计数，不开放综合期原表读取。



Skills边界（2026-10-10用户确认）：安装目录及安装/启用/禁用/删除全局管理；加载/卸载、list_skills的loaded状态和指令注入属于当前会话。网页管理与AgentLoop共用一个目录所有者，全局禁用/删除清除所有会话的对应加载；重新启用不自动恢复加载。其他会话的加载状态不得成为本会话效果证据。

模拟边界（2026-10-10用户确认）：optimize保留现有份额分配和逐次剪裁，称约束分配候选；交付前复核全部默认/显式上下界与目标，越界不交付，未找到不等于数学不可行，不宣称最优/最小变更/最小二乘。每组零或负基数拒绝，不新增优化器。sensitivity保留乘法/等比例算术和完整分组；零总量且目标非零时保留基线/目标/缺口，比例及分组反推未知；维度字符串仅接受唯一匹配，缺失/歧义拒绝。算术情景不授予因果或预测验证。

## 4. 最终覆盖与缺口

覆盖只从最终接受内容投影一次；状态属于回答对需求的结果，不是第二任务状态机。

| 状态 | 准确含义 |
| --- | --- |
| answered | 所要求事实/解释已经交付且对应校验满足；咨询不要求数据回执 |
| partial | 已交付部分，并定位剩余各项缺口 |
| not_computed | 所需计算未成功进行，准确说明缺文件/未执行/预算等实际原因 |
| evidence_insufficient | 现有证据不能支持所问结论，例如无对照不能证明增量因果 |
| needs_confirmation | 仍有影响该项的业务口径未决，独立项继续 |
| failed | 工具/合同/交付等内部失败；不能写成用户缺数据 |
| withdrawn | 用户明确撤回，退出有效分母且有来源记录 |

测试分母由独立标注的原请求确定。对已有数据且方法足够的必答项，not_computed/failed/泛化缺口均不算成功；预设缺口只在对应场景合格。原值与日期端点不自动证明另一个含首尾日数目标；一段解释通过不证明同目标其他被拒解释已经完成。

## 5. 封闭事实、详情和预算

- 对象、指标、组名、值、单位、粒度、窗口、分母、方法与版本成组。已核派生必须重算操作数；百分比与百分点、金额与数量不得混淆。
- 22400×5.1%=1142.4，22400×1.417%=317.408；显示舍入与计算精度分开。零分母、负基线、None/NaN/Inf、混合单位具体处理；不能从普通日期/版本号/引用例子猜新事实。
- 9月1—12日含首尾12天；日历并集与连续跨度区分。D1—D7观测允许描述/拟合；没有相应依据不发布D30预测。另一当前来源有效D30可独立交付。
- 12组/六来源/末项必须完整可访问；用户明确要求正文全列时正文满足。详情保存前不能有损压缩，同ID异内容不覆盖；文件/摘要失效明确unavailable/invalid，不跨会话取替代品。
- 既有宿主2048事实manifest、模型草案/片段128引用及审核响应64000字节解析上限保留；模型与审核输入统一按完整请求token容量核算，模型视图65536 tokens为软目标，必要交付允许扩展到实际剩余上下文。使用完整组、去重元数据、可核详情引用和明确未读范围；不得截断必要数值/事实组或静默丢目标。
- 审核只带相关引用与必要原需求/全篇限制，完整证明由宿主持有。真正超限时保留可核事实，相关开放义务未核；不追加审核、伪报覆盖或写成已完成。该降级不签收原本可完成的质量验收。

## 6. 开放解释、行动与一次审核

数据相关开放内容每轮至多一次审核，纳入现有Provider预算和账本。纯概念咨询未引用具体数据结果时不强制审核；模型不能自标knowledge绕过。草案生成属于既有AgentLoop终局轮次，不增写作Agent。

审核输入同一冻结快照的原需求、目录及事实强度、结构节点、明确条件、整篇来源/限制；finding必须定位已知片段和当前身份。审核不返回替代值或新事实。按整篇核对共享限定，也检查可能局部误导；不要求每段逐字重复所有术语。

可定位坏引用/坏格式只拒片段；全局snapshot/session/revision身份错拒整草案。审核不可用、预算不足、返回错ID/无定位/错版本则相关开放内容未核，独立事实保留。没有二次语义复核或循环重写；已有单次协议格式恢复不能换证据或重新审核。

条件行动明确对象、未来窗口、触发条件、动作和验证/停止方式。阈值来自用户规则或已核事实；假设示例必须标示，不能假称当前已满足。AND条件不能丢一项；不因没有因果证明删除所有验证性行动。合法方法支持的推断/因果/预测按真实边界保留。

## 7. 接受答案、历史和展示

终局冻结后统一验证、组合、覆盖和提交；持久化成功后才能公开正式答案，每轮一个terminal。生成草案和拒绝内容不能先流到正式正文再删除。图/表/公式用当前接受对象与真实artifact引用，由宿主原位渲染；模型自由文本图标记不赋权。

只改表达时核原接受答案和当前适用性，不重算；正常继续、换版、撤回/替换更新真实目标。明确展示历史比较保留旧来源历史，不能借旧值背书当前版本。

大改不兼容：旧协议历史只读，不迁移运行状态、不保留旧reader/fallback执行链。新协议续问/确认/压缩/刷新/导出完整。分支只继承聊天，父答案历史不为分支授事实权威。

压缩保存可核原始轮次，模型上下文实际缩短；公开历史/导出读取同一归档的原答案，不能用模型摘要替换。工作台只投影事实与开放状态，不重判；报告不暴露内部路径/JSON，审计仍保留原证明。

## 8. 追溯与验收

旧read-old/write-new改为只读历史；旧隐藏绑定/selector改为当前单一结构协议；旧零新增审核规则改为已批准一次有界审核；旧“所有交付完成才能推进计算”改为计算依赖与最终开放义务分开；不可变交付集合改为受控追加。全部替代以[冲突表](../audit/2026-10-10-project-retrospective.md)和[180项映射](../superpowers/validation/2026-09-30-trusted-answer-pipeline-acceptance.md)核对。

既有历史结果可作反例与能力参考，不能冒充当前自然生成。宿主确定性事实、全链交付、开放语义质量、视觉和真实Provider各自验收。两批自然完整通过、硬门与内容评分的精确定义只见现行验收；不承诺任意模型输出绝对正确。
