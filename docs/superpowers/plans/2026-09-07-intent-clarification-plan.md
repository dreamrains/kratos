## 2. 问题与目标

会话 `9810fe7bacf6` 要求分析省钱卡的功能效果、收益、复购和付费行为；会话 `9959216b6a4a` 要求拟合已有留存率曲线。二者首次都被同一 Retention & Lifecycle 方法确认卡片暂停。

已证实的根因是：模板类型直接创建待确认项；静态问题没有绑定实际业务缺口；计划模板可能用局部指标取代整体任务。无法证实两次历史选择是否来自 LLM 失败后的关键词回退。优化不能建立在“历史 LLM 必然超时”的假设上。

目标是让 Agent 自主完成已授权的分析，把用户介入留给真正改变分析结果、且无法从请求、有效历史决定或数据中确定的业务选择。减少提问与维持证据可信度必须同时验收。

## 3. 已裁决产品原则

1. **方法运行不需要通用审批。** 留存、回归、分类、预测或因果工具的类别名称，均不是单独的提问理由。不把模板审批简单下移成逐模型审批。
2. **业务歧义需要具体化。** 例如净收益的成本边界、复购的分母、观察窗口、文件指代。先查已提供信息；可安全确定时执行并披露口径。
3. **用户同意不能替代证据。** 缺对照、缺字段、未观测外推、数据范围错误、失败收据等由现有数据/方法/发布约束处理；用户批准不会使其变为已验证。
4. **主目标决定分析主线。** 指标清单中的“复购”可以产生子任务，不能单独缩窄综合功能分析。计划须覆盖显式子问题或给出逐项具体缺口。
5. **保留 LLM 优先和确定性回退。** 当前入口已经先尝试 LLM；本次改善回退语义与可观测性，不另加长文本 LLM 调用、重试、模型切换或任意延长超时。
6. **复用业务决定而非方法许可。** 同一语义决定在相同有效范围内不重复问；目标、分母、窗口、有关数据/版本或假设实质变化时重新评估。
7. **沿用现有单运行时。** 不新建规划器、审批数据库、独立问答 Agent、并行工作流或通用规则平台。
8. **技术字段不进入用户决策负担。** 问题展示缺什么、为什么影响结果、具体选项；方法名、哈希和 spec ID 留作内部说明或审计。

原则与 [Route A 架构设计](../specs/2026-08-23-route-a-top-architecture-design.md) 的“方法不是确认理由”、[能力清单](../../audit/2026-08-25-capability-preservation-ledger.md) 的“用户独占语义选择”一致。对本专题，旧计划/测试中“所有高风险方法必须批准”的要求由本计划取代；其数据安全、真实歧义、证据和副作用边界继续保留。不得据此改写其他专项的历史报告或宣称其已验收。

## 4. 范围与不做事项

纳入：方法选择及计划覆盖；模板自动确认；`question_need_detector`；`analysis_entry` 与既有 pending 门控；模型直接 `ask_user_question`；运行时策略及非阻塞结果处理；工具能力审批；有效决定复用；旧会话恢复；CLI/Web/SSE 一致性；选择和提问来源记录。

不纳入：统计引擎重写、新的因果识别能力、发布等级放宽、假设算法重构、受众画像改造、全面 UI 改版、历史会话批量重算、真实 Provider 参数调优。现有副作用/路径/权限控制不因本专题而改变。

“尽量少问”不是零提问指标。必要业务决定必须仍可询问；无关方法审批必须消失。未解决依赖不得通过替用户编造业务答案来放行。
