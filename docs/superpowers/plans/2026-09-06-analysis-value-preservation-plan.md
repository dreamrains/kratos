## 2. 背景与问题定义

项目面向自然语言数据分析，已有意图分类、工具执行、分析计划、EvidenceRecord、验证报告、竞争假设、对话发布与 Workbench。用户希望保留分析能力和业务价值，同时保证结果可信。

本次问题不是“回答字数不够”。诊断发现，同一条分析链中既有对有效内容过度限制的规则，也有对假设支持判定不足的规则。只减少警告或放宽阈值，会把两类问题混在一起。

需要分别处理以下内容生命周期：

1. **未执行**：误判意图或数据作用域，使本可完成的任务没有进入分析。
2. **未进入合成上下文**：早期来源或关键分组在摘要中被省略。
3. **候选正文被拒绝**：局部语句触发规则，整份回答无法发布。
4. **正文存在但工作台未展示**：只投影中高置信已验证结论，并限制六条。
5. **错误升级**：文本相关或旧证据被误认成假设已获支持。

这五种情况必须有不同的诊断记录、修复方式与验收用例。不能把“未在工作台出现”统计成“数据被删除”，也不能把“工具执行成功”统计成“结论已验证”。

## 4. 已确认原则、目标与非目标

### 4.1 已确认原则

- 保留能由数据支撑的描述性发现。
- 允许有依据且明确标注的待验证解释；必须说明尚缺的区分性证据。
- 允许有证据支持的条件性、可逆建议；说明适用条件、跟踪指标与停止条件。
- 已验证结论继续要求当前、同范围、可追溯且通过对应检查的证据。
- 业务人员、分析师、管理者适配只改变重点与表达，不改变事实、限制和证据门槛。

### 4.2 交付目标

| 目标 | 完成后的可观察行为 |
|---|---|
| G1 减少不必要保守 | 中文建议与等价英文请求策略一致；描述性计算不被不适用的推断规则自动降级 |
| G2 保留分析价值 | 每个主要问题有答案或具体缺口说明；有效内容不因局部误拒绝或摘要选择静默消失 |
| G3 保证路由正确 | 客套话、否定句、咨询加执行的复合输入不会覆盖主任务；无关数据问题不阻断目标任务 |
| G4 实现身份适配 | 同一证据可按业务、分析、管理视角呈现；会话中可切换，不依靠增加 Agent 数量 |
| G5 补齐竞争假设 | 候选、支持、反证、冲突、未决、失效均有可追踪依据；旧证据不能继续支持新版本 |
| G6 保持已有能力 | 分析、数据操作、确认、工具预算、导出、SSE、刷新和会话隔离不回退 |

### 4.3 非目标

- 不重建第二个 planner、EvidenceStore、Workbench runtime 或 `/v2` 产品入口。
- 不把回答长度、图表数量、工具调用次数作为分析质量的替代指标。
- 不承诺识别所有自然语言中的因果错误；明确确定性检查的覆盖范围与未决情况。
- 不增加用于“角色扮演”的真实 Provider 调用；语义分类沿用现有辅助路径。
- 不自动恢复旧 Trust Inspector 或历史复杂面板。
- 不在本专项默认修改模型、endpoint、重试策略、调用限额或确认安全边界。
- 不自动执行历史会话批量迁移、删除数据、提交、推送、合并或部署。

## 6. 阶段依赖与开发流程

主顺序：`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8`。

P3 / P4 的实现可以在接口冻结后独立开展，但合入顺序仍需逐阶段检查。此处“可以独立开展”只是依赖说明，不授权启动多个代理或新任务。P6 依赖 P3—P5 的内容分类和当前证据状态，不能先写 UI 再猜后端语义。

每阶段遵循：确认输入基线 → 新增能区分正确/错误行为的 RED 用例 → 最小实现 → 定向回归 → 阶段记录。测试契约需要调整时，写明原需求、已确认的新需求以及仍须保留的负例；不得为了绿灯删除测试或放宽 oracle。

### P1：阻止假设被错误升级

**目的**：先建立可信度底线。

任务：

1. 为否定证据、不同 dataset/plan/version、纯文本重合、过期支持添加负例。
2. 文本重合降为候选关联信号，不产生 supported。
3. 重算支持/冲突关系，不能只追加旧 supporting_evidence_ids。
4. 旧无绑定假设保留为历史记录或未决候选，不能自动成为新证据支持。

修改面：hypotheses、trust_workflow_runtime 及对应测试；必要时添加小范围关系校验函数，不创建独立服务。

**退出门槛**：H01—H05、H10 全通过；错误数据或反证不会得到 supported；有效旧数据不被删除。结构化正向支持闭环在 P5 完成，P1 允许安全地维持未决。

### P2：修复意图、范围和回答策略

**目的**：让正确任务进入分析，并按用户需求决定输出深度。

任务：

1. 区分纯问候与“问候＋分析”；对否定和复合意图进行冲突判断。
2. 明确执行任务与咨询请求的优先级；不让“分析建议”等子串覆盖主任务。
3. 细化和入口共用当前 scope；兼容 compact ref 与完整 contract。
4. 区分聚合留存描述、用户级留存、预测、因果任务所需数据。
5. 将建议需求、分析深度与证据门槛分开；覆盖中英文及简短但要求建议的输入。
6. 保留 no-data、真实缺字段和未解决高风险确认的阻断行为。

**退出门槛**：I01—I12、S01—S08 通过；相同明确意图不因语言改变策略；辅助调用不出现隐式无限重试；常规操作与咨询仍可达。

### P3：按主张检查发布与校准

**目的**：保留合规观察和解释，阻断无依据断言。

任务：

1. 区分观察、推断、因果、预测、假设、行动建议以及边界/补数说明。
2. 改写外推检查：识别具体主张及其来源范围，处理否定、转折、混合句和多数据源。
3. 给检查结果提供违规位置和稳定原因；保持一次受预算约束的修订，不新增无限重试。
4. 对不合规主张提供局部修订或明确保留边界；完整回答再次检查后才能发布。
5. 校准区分数据内描述与总体推断，时间窗口从结构化信息读取。
6. 逐工具核查已执行检验元数据，不能因本轮某处有 p 值就为全部主张背书。

**退出门槛**：N01—N12、C01—C08 通过；合规 D30 边界/采集计划可发布，无依据预测仍拒绝；同句中否定不能掩护另一句断言；存在警告不导致无关事实被删。

### P4：保留关键证据与可恢复上下文

**目的**：在有限上下文中优先覆盖用户问题，遗漏可发现、可恢复。

任务：

1. 先按当前任务过滤来源与 evidence，再选择和分配摘要预算。
2. 构建“用户子问题 → 相关证据/结果引用”的覆盖映射。
3. 对比较、拟合、分组等结果保留解释所需字段组合；不能只保留数值丢失组名/分母。
4. 覆盖完整候选分组后再选摘要；省略项保留数量、稳定引用和原因。
5. 中等与大型工具输出均先可靠持久化再压缩，检查碰撞和读取失败。
6. 新证据进入后刷新发布包；相同来源 id 但内容变化不能复用旧摘要。

**退出门槛**：E01—E10 通过；关键子问题证据召回率 100%；省略项有可恢复引用或明确不可恢复原因；原结果不丢失；超过预算的任务不会把缺失部分称为完成。

### P5：竞争假设的完整闭环

**目的**：把“列出几种解释”落实为可追踪、可更新的分析过程。

任务：

1. 建立显式假设身份、证据关系和范围绑定；扩展现有工具可见 schema 与持久化校验。
2. 支持候选、未决、支持、反驳、冲突、失效和数据不支持等状态，详细规则见技术设计。
3. 有效关系还需满足主张类型要求；已验证描述性变化不能升级为因果解释。
4. 新证据、计划/版本变化、恢复会话和最终发布前刷新状态。
5. 将假设对比、反证、未排除项和下一项区分性检验送入回答合成。
6. 将“必须排除一个替代解释”改为“如未排除，必须说明未决及缺口”。

**退出门槛**：H01—H12 通过；正向有效支持、反证与失效均有测试；中文证据不依赖英文模板文本重合；一次回答后补充证据能改变相应状态且不污染其他假设。

### P6：身份适配与渐进展示

**目的**：让用户看见有价值的内容，同时理解它属于哪类证据状态。

任务：

1. 区分 audience 与 proficiency；显式当前请求优先，允许会话中改变。
2. 实现业务人员、分析师、管理者的重点映射；不额外调用专家 Agent。
3. 保持已验证结论区，只让当前通过项进入；六条以后的有效项可展开。
4. 增加默认折叠的待验证发现入口，含依据、缺口、下一步；不展示原始内部 JSON。
5. 刷新、会话切换、导出时保持内容性质和范围一致；不把历史内容升级成当前已验证。

**退出门槛**：A01—A08、U01—U08 通过；同证据不同角色事实一致；界面不能只靠颜色区分类别；至少一组本地真实浏览器用例通过后才能声称 UI 已验证。
