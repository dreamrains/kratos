## 2. 必須保持的区分

- 未执行、未进入综合、候选被拒、工作台未显示、错误升级是不同环节，必须沿实际链定位，不能统一叫“模型回答不可信”。
- observed事实、inferential统计推断、causal因果、predictive预测、hypothesis假设、conditional_action条件行动、limitation限制按真实依据分别允许。合法因果设计/验证预测不能被一律禁用。
- 计算准确不能证明业务解释；confidence或样本量不能代替方法检查。来源/范围/单位未知如实说明，不随回答措辞加新词表。
- 有用行动可为条件试点、验证/补数据步骤，包含适用对象、触发、评估/停止条件；没有干预因果证据不等于所有建议都不允许。

## 3. 当前承接规则

结构claim保护事实，一次局部审核处理数据相关开放内容；旧整篇改写/复核循环和零审核限制已被用户确认替代。计算DAG只依赖已核事实/产物/关系，开放义务留在最终覆盖。旧会话只读；新协议生命周期完整。原84项目标全部保留，机制替代逐项见[统一验收](../validation/2026-09-30-trusted-answer-pipeline-acceptance.md)。

验收必须同时证明合法内容可交付、错误内容不升级；必答的可算结果不能以缺口代替。长度、图数、测试数、代码行数都不是价值指标。VP历史建议的1—5分量表保留为参考；现行硬门和统一0—10内容量表见统一验收，不能实施后择优换评分。
