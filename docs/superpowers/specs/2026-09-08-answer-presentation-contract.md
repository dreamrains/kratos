# 回答内容与排版规范

现行整理：2026-10-10。本文规定表现要求，不记录历史实施状态。技术合同见[现行设计](2026-09-30-trusted-answer-pipeline-redesign.md)，验收见[统一验收](../validation/2026-09-30-trusted-answer-pipeline-acceptance.md)，状态只见[唯一计划](../plans/2026-09-22-analysis-agent-trust-reset-plan.md)。旧字节已归档。

## 1. 先确定必须说什么，再决定怎么排

内容优先级由用户目标、必答项和已计算结果决定。默认先给直接回答，再组织关键证据、解释和下一步；根据内容决定章节，不设通用的 2–4 节上限。

| 内容 | 保留要求 | 可压缩方式 |
|---|---|---|
| 用户明确要求的指标、比较、方法或解释 | 逐项有回答，或具体缺口 | 多指标合并为表格，不能合并掉不同口径 |
| 影响解读的分母、窗口、单位、零值政策 | 与对应结果一起出现 | 同口径共享一条表注；不同口径分别标明 |
| 已计算且影响判断的模型比较、敏感性 | 给出对照及影响，避免只报赢家 | 小表或一句准确量化说明 |
| 竞争解释与业务含义 | 区分观察、可能解释与条件建议 | 合并重复边界，保留区分证据和条件 |
| 可选延伸和背景 | 按用户需要与证据价值选择 | 放文末、可访问详情或明确省略 |
| 收据、代码、哈希、内部路径 | 审计持久化 | 用户正文不默认展开；技术审计请求例外 |

“已计算但没展开”须与“未计算”“证据不足”区分。引用完整表时给出有意义名称和可打开入口，不能让用户自己拼 receipt id 或内部路径。

## 2. 深度和用户偏好

| 请求类型 | 预期回答 | 禁止行为 |
|---|---|---|
| “只给公式/简短回答” | 公式、必要适用范围；明确要求的第二问题仍需回答 | 强制长报告、遗漏必要单位/边界 |
| 普通拟合/比较 | 结果、关键对照、口径/误差及适用性；已有敏感性有价值时保留 | 没说“详细”就只给一个数；附无依据行业评级 |
| 多指标/要求验证计算方法 | 总览＋分组结果表＋方法和限制，完整响应指标 | 普适四节模板挤掉计算流程或后半指标 |
| 咨询/明确要建议 | 有证据的条件式建议、未决解释、验证方法 | 因无因果证明删除所有建议，或将建议写成确定收益 |
| “不要建议/不要图标/纯文本” | 尊重明确偏好 | 关键词误判后仍强塞建议、图标或图形 |
| 受众切换 | 调整术语与重点 | 数值、范围、证据等级随身份改变 |

偏好优先级：本轮明确要求 > 有效会话偏好 > 按任务复杂度推导 > 通用默认。允许简短但多问题、详细但不建议等组合，不用单一深度枚举替代所有约束。

## 3. Markdown、图标、公式与图表

- 标题表达实质主题，如“拟合结果与误差”“购卡前后同窗口比较”，不每条发现重复五个空泛标题。
- 相同口径的多组值优先表格；表头写单位，必要时写分母。操作步骤用列表，关键结论适量加粗。
- 图标可用于帮助识别发现、限制、下一步，属于可选呈现。没有数量配额，不依赖颜色或 emoji 单独传达状态；“已验证/未验证”等语义必须有文字。
- 公式使用现有 KaTeX 支持的数学语法并解释变量和单位；不能把代码块当通用布局容器。
- 趋势、分布、分组对比确实适合图形时调用 create_chart，来源、范围与正文保持一致。禁止为丰富外观捏造数据或恢复无来源 Mermaid 分析图。
- 图表通过当前结构草案中的artifact引用，由宿主核当前会话、来源、版本与内容摘要后原位渲染。模型自由文本标记不授予事实或图表权威；不恢复旧wrapper/隐藏协议作为另一发布通道。
- 图放在解释它的结论旁。无关/重复图不强制内联；有意义但只作为补充的图提供说明。不能以“图表已生成”替代需要的解释。
- 图表失败时使用已验证数字表并说明具体缺口，不画虚构备用图。宽表允许容器水平滚动，正文不能整体溢出屏幕。

所有正文通过现有 Markdown 安全渲染和链接处理。任何引用规范化仍须查验真实artifact，不以任意正则删除附近内容或猜来源。

## 4. 可审阅样例：保留口径价值

以下是使用诊断中已出现的量值写出的**呈现片段**，不是重新完成留存分析，也不为原先排零政策或未来预测背书。

> **两种平均口径存在差异，最大为 0.277 个百分点。** 普通均值让各批次权重相同；按新增人数加权则让较大批次占更大权重。本次计算都按已执行的排零政策处理，零值是否确为未观测仍未确认。
>
> | 留存日 | 普通批次均值 | 按新增人数加权 |
> |---|---:|---:|
> | D1 | 17.080% | 16.803% |
> | D7 | 5.100% | 5.028% |
>
> 选择哪种口径取决于要描述“典型批次”还是“用户加权整体”。目前结果可以用于交代口径影响，不能据此证明未来批次预测准确。

比只写“拟合很好，需注意局限”更有解释价值；也没有把差异自动评价为“可以忽略”。是否达到业务容忍阈值需要具体标准。

九指标省钱卡请求的建议组织：结论总览；收益/复购/卡型；同用户同窗口付费指标及公式；金额分布；连续付费与其他已计算解释；局限与条件建议。只是一种分组方式，不是固定六节模板。ARPU 与人均付费若同口径可以同格解释，日均总额和人均日均金额不能混为同一指标。

## 5. 不应恢复的“丰富内容”

不得从拟合优度推出用户类型、行业评级或运营措施的因果收益；不得把无检验写成不显著；不得用确认同意替代证据；不得把未知零值解释成未到期；不得通过长边界段落掩盖正文错误数字。

有价值的扩展可以是：已观察到什么、哪些解释仍可能、哪项已计算对照支持/削弱该解释、还需什么数据或实验。必要时给出条件式下一步，但条件和停止标准需有依据；没有数据支撑的阈值不能伪装成优化结论。

## 6. 展示验收边界

内容评审先核对量值、需求和解释，再看层次。字符数、标题数、图表数、emoji 数仅作变化观测，不设达到 5 月水平的门槛。

本项目当前以电脑端智能体为产品范围。本地浏览器验收覆盖 1440px：标题、表格、公式、正确/错误图引用、键盘可达入口；刷新后正文内容一致；Markdown/现有导出支持的格式可打开。静态导出不能显示交互图时使用同版本静态替代或明确图链接，不假装保留了交互能力。移动端 UI 不作为本次实现或合并门槛，另行规划。

本规范不要求新增 PDF/Word 导出能力；只验证项目当前支持的导出路径。没有浏览器截图与文件打开证据时，不能宣布展示验收通过。
