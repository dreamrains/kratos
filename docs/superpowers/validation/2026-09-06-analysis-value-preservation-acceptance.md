## 1. 验收原则与证据等级

| 等级 | 能证明什么 | 不能代替什么 |
|---|---|---|
| L0 静态检查 | 模块/字段/调用连接和受控范围 | 运行行为 |
| L1 纯函数与离线单元测试 | 具体输入下的确定性判定 | 完整分析链和模型质量 |
| L2 离线集成回放 | 真实工具、状态与脚本化模型响应的完整链 | 真实 Provider 的语义理解和生成质量 |
| L3 本地真实浏览器 | 当前源码 Web/SSE、交互、刷新和导出的实际行为 | 真实 Provider、正式 Web 进程或部署 |
| L4 授权真实 Provider | 冻结模型/输入/源码下的真实回答与调用消耗 | 未运行的场景、其他模型、staging/production |

声明结果时同时报告等级、源码身份、场景、通过/失败/跳过/未启动数量。截图不能代替数值 oracle；API 200 或模板字符串测试不能代替浏览器操作；一次通过不能代表所有随机模型运行都可靠。

每条修复用例至少包含：原问题 RED、正确行为正例、相近错误行为负例、正常能力回归。不能只测试实现中出现了新函数或提示字符串。

## 2. Fixture 与 oracle 设计

| Fixture | 规定输入 | 可独立核对的真值 |
|---|---|---|
| F-SALES | 12 条订单，每条金额 10；订单集合完整且无缺失 | 当前 12 条记录合计 120；不能据此推广到全部市场 |
| F-GROUP | 四个渠道 A/B/C/D，对应金额 1/2/3/999 | 最大值属于 D；分组名与数值不可拆开 |
| F-SIX | 六个独立子问题，各有一个成功计算与绑定证据 | 每个问题的来源、答案或缺口可追踪；不能只保留后四项 |
| F-RET7 | D1—D7 聚合留存观测，D7=0.10；无 D30 观测/预测依据 | D7 为 10%；D30 未知，允许建议补充至 D30 的观测 |
| F-TWO-SCOPE | A 为 F-RET7，B 有有效 D30 观测 0.08 | B 的 D30 可描述；A 的范围不应覆盖 B |
| F-HYP | 同 dataset/plan/version 的假设、结构化证据与方法条件 | 支持/反驳由预先规定的可计算谓词决定；纯文字不是 oracle |
| F-STALE | 相同数据名不同版本，以及同版本不同计划 | 旧证据不得为新范围背书 |
| F-BAD-OTHER | 当前目标数据 ready；另一无关数据 blocked | 目标独立任务可执行；若计划需要坏数据则仍阻断 |
| F-COMPACT | 含尾部关键字段的中等/大型工具输出，以及同 id 不同内容 | 压缩前后原文内容摘要可核对，尾部事实可恢复 |
| F-AUDIENCE | 固定事实、证据、限制，三种身份与熟练度表达 | 数值/证据集合不变；呈现重点变化 |

Fixture 由独立手工计算或与产品不同的简单 oracle 校验。不要用被测函数自己生成 expected。数值比较容差按方法先冻结：整数计数精确相等；浮点由 fixture 明确容差，不设可掩盖错误的统一宽松阈值。

真实数据场景用已存在且合法可访问的数据副本，另行冻结真实输入摘要。不得把合成 fixture 的通过率当成真实业务回答通过率。

## 6. P3：置信度与限制（C01—C08）

| ID | 设置 | 预期 |

通过条件：关键子问题证据召回率 100%，关键数值/单位/范围不丢失；合法省略都有可审计原因和有效引用或明确失败说明。不能靠把全部原始数据塞入 prompt 通过。

## 11. P7：本地真实浏览器纵向场景（B01—B06）

Provider 必须禁用，使用明确脚本化模型响应驱动真实本地工具/状态/Web。输入夹具隔离在新测试目录，不写入用户生产会话。脚本化响应可以控制模型行为，但不能 mock 掉本次被测的校验、持久化、投影和 SSE 消费链。

| ID | 操作过程 | 重点核对 |
|---|---|---|
| B01 | 加载 F-SALES → 中文分析＋建议 → 最终回复 → 刷新 | 120 的描述性事实保留；建议有条件；正文与工作台一致 |
| B02 | 加载 F-RET7 → 发布 D7＋不能预测 D30 → 尝试错误 D30 断言 | 合规边界可见；错误断言不会先流到浏览器再删除 |
| B03 | 多数据源/六子问题 → 中途压缩 → 综合回复 → 展开/导出 | 第四关键组与早期来源保留，省略可解释，导出完整 |
| B04 | 创建竞争假设 → 支持/反证 → 补新证据 → 修改版本 → 刷新 | 正确的未决、支持/冲突和失效变化，身份与会话无污染 |
| B05 | 固定分析结果 → 业务/分析师/管理层连续追问 | 呈现重点变化，数值和证据等级不变，普通对话可继续 |

“0 个错误”仅指冻结必测集的观测结果，不是对任意未来输入的绝对保证。超过预算的场景记录未完成，不修改分母让通过率变高。

### 12.2 业务可用性评分

每项 1—5 分，评分前冻结要素，至少由能理解业务问题的审阅者复核：

- 解释价值：是否将数据与当前业务问题连接，并区分事实和解释。
- 行动价值：是否给出有依据的条件、行动、指标与停止条件。
- 假设区分：是否讨论真正不同的解释与可区分证据，而非同义改写。
- 身份适配：是否满足相应角色的关注点，且不丢失必要限制。
- 可读性：结论优先，结构适当，警告不机械重复，正文不倾倒内部数据。

建议通过标准：每项至少 3/5，冻结样本平均至少 4/5；有合格等条件基线时不得出现未解释的关键维度回退。该评分阈值是本方案建议，在 P0/P8 冻结时确认，不能执行后按结果改阈值。任何软分数都不能抵消硬门槛失败。
