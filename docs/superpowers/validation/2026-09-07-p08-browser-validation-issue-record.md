## 核心问题（P1）

### P08-01：静态方法计划导致不必要的确认

- **触发：** M02 提问“请计算并解释 D7 留存；判断当前数据是否可以预测 D30。若不能，请明确说明缺失证据与下一步。”
- **实际行为：** 系统在分析前要求确认“Forecast & Decision Simulation”方法计划，并要求补充“目标口径、时间窗口和比较对象”。
- **为什么是问题：** 用户已经指定了当前描述性指标、预测可行性的边界判断和期望的缺失证据说明。方法名称、预测关键词或 D30 不能单独构成需要用户确认的业务语义缺口。
- **影响：** 阻塞一个本可直接完成的核心分析请求；也会让用户误以为系统把内部方法选择转化为额外决策。
- **修复方向：** 按意图澄清计划实施：只有分母、时间窗、人群、归因口径、业务目标等会实质改变结论且无法安全推断时，才提出一个可回答的确认问题；内部方法选择不再单独阻塞。
- **回归用例：** Q13：D1--D7 留存数据中，请求解释 D7 并判断能否预测 D30，必须直接给出 D7 描述性结果与 D30 证据边界，不能由“forecast”“D30”或方法名称触发确认。

### P08-02：证据绑定守卫在正确分析后错误终止

- **触发：** M02 在用户选择继续后执行 D7 / D30 分析。
- **实际行为：** 页面未发布无依据的 D30 数值，但终端以“时间点数值主张未绑定到具体来源”等错误结束，提示必须先把 Python 结果解析为证据、限制、任务状态或用户确认。
- **为什么是问题：** 失败前已经具备应答所需的正确方向：给出可验证的 D7 描述性事实，并对 D30 只说明证据不足。守卫没有把受约束的拒绝/边界结论视为有效完成状态。
- **影响：** 即使系统避免了编造，也无法完成用户任务，属于核心流程失败。
- **修复方向：** 在实现阶段追踪 Python 回退结果到证据、限制和最终叙述的归并路径；允许“无法预测，缺少何种证据”的边界结论正常终结，仍禁止未绑定来源的数值主张。
- **回归用例：** Q13 完成时必须产生最终答复；答复可拒绝 D30 数值预测，但不得因该拒绝而进入探索/终止循环。

### P08-03：显式竞争性假设请求被误判为路线选择不清

- **触发：** M04 明确要求“提出并检验至少两种竞争性假设”。
- **实际行为：** 系统先要求在 `trend` 与 `period_compare` 等内部分析路线中选择。
- **为什么是问题：** 用户已明确要竞争性假设和检验，路线选择是系统的内部执行决策；该确认既不补足业务语义，也不提升结论可信度。
- **影响：** 阻塞竞争性假设这一核心能力，并引入用户不应承担的内部方法决策。
- **修复方向：** 在意图识别中识别“竞争性假设、提出假设、检验解释、验证假设”等明确任务动词，使其优先于“多条可用路线”的泛化澄清规则；保留真正缺少指标、比较对象或业务口径时的语义确认。
- **回归用例：** Q14：显式要求“提出并检验至少两种竞争性假设”时，系统自动选择内部路线、直接给出至少两种假设的证据状态和限制，不能要求选择 `trend` 或 `period_compare`。

### P08-04：版本重载后模型消息历史违反工具协议

- **触发：** M04 将数据从 v1（10、20、20）重载为 v2（10、10、10），并要求将其视为同一对象的新版本、保留历史。
- **实际行为：** 界面报告旧版本已归档、新版本已更新，随后 Provider 返回 `BadRequestError`：`Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`。
- **为什么是问题：** 数据版本链路表面完成，但后续分析因构造了不合法的模型消息序列而无法执行。
- **影响：** 版本管理后的核心分析不可用，且可能影响同一会话中任何使用工具的后续请求。
- **修复方向：** 检查版本重载、会话恢复和消息裁剪/拼接处对 `assistant.tool_calls` 与 `tool` 消息的成对保留规则；在送往 Provider 前验证消息序列合法性，并以可恢复的方式处理孤立工具消息。
- **回归用例：** M04 v1 完成后重载 v2，再提出竞争性假设请求；必须保留版本历史并得到正常答复，不得出现工具角色协议错误。

## 次要问题（P2）

### P08-05：无数据时的提示过长且夹带无关路线

- **触发：** M06 在未加载数据时输入 `missing_orders`。
- **实际行为：** 系统正确拒绝编造，但给出偏长的说明、多个未来分析路线和额外业务背景问题。
- **影响：** 不影响可信度和主流程，但增加恢复成本。
- **修复方向：** 保留“没有数据、不能形成结论、下一步如何上传”的最短可行动提示；只在用户问题确实依赖业务目标时再提问。
- **回归用例：** 无数据请求应在简短回复中说明缺少数据并给出一个上传/选择数据入口，不生成与当前请求无关的多路线菜单。

### P08-06：导出结果未独立确认文件落地

- **触发：** M06 中点击“导出为 MD 文档”。
- **实际行为：** 浏览器导出动作已执行，未在本轮独立取得可核对的下载文件或路径。
- **影响：** 导出功能本身尚不能标记为完全验收，但不阻塞分析主流程。
- **修复方向：** 下次浏览器回归时检查浏览器下载记录或导出完成反馈，并核对导出内容与当前会话一致。

## 已验证的正向行为

### M01：可信度边界

对单渠道、金额恒定且仅 12 天的数据，系统明确说明缺乏变化、对照和可归因信号，未虚构行动建议。该样本只验证不编造，不能用于评价行动建议质量。

### M03：多来源内容保留

用户要求保留 6 个来源。最终回复逐项给出 `source_1` 至 `source_6` 的数值变化，并汇总 210 到 231、总增量 21、共 12 行。未见内容被固定数量截断。

### M04：竞争性假设内容质量（仅首次运行）

在人工选择路线后，系统输出了线性增长、阶跃后稳定及未决解释等竞争性假设，给出了各自证据状态、样本量和低置信度限制。这说明假设生成与边界表达能力存在；当前失败点是前置确认和版本重载后的协议错误。

### M05：多角色区分

面对同一事实，业务角色获得决策步骤和补数建议，分析师获得公式和样本限制，管理者获得资源/决策含义，通俗角色获得易懂解释，技术角色获得来源哈希和可复现边界。跨角色的核心事实保持为 10 到 11、增量 1（10%）、样本量 2、一个来源，未发生事实漂移。

### M06：安全恢复与状态保持

未加载数据时系统没有形成虚构结论；随后只要求描述性 D7 时，直接返回 D7=10%、不做预测、并说明没有 cohort/日期等范围限制；刷新页面后会话消息仍被保留。

## 不作为当前阻塞项的核对

1. **Provider 请求账本：** 本批因本地旧服务进程命中导致账本为空，不能确认本批的调用次数。按当前优先级，留到下一次真实浏览器、真实调用矩阵中与服务进程身份一并核对。
2. **浏览器载体：** Edge 对本地文件上传的限制使本次转用应用内浏览器完成上传。这是当前环境限制，未显示为产品功能缺陷。
3. **完整 P08 验收：** 在 P1 修复后，以全矩阵重跑统一确认。此记录不把已通过样本外推为全量验收。

## 实施顺序与完成标准

1. 先处理 P08-01 和 P08-03：将确认从“内部方法/路线选择”收敛到不可安全推断的业务语义缺口。
2. 随后处理 P08-02：让有来源的描述性结论和有明确限制的预测拒绝能正常结束。

4. 最后处理 P08-05；P08-06 与请求账本核对在下次真实浏览器、真实调用验证中复核。

**当前通过标准：** Q13、Q14 及版本重载回归在离线测试中稳定通过；既有的真正语义确认仍会在缺少会改变结果的关键口径时出现；随后再执行一次完整 P08 矩阵，统一判定验收状态。
